# Implementation decisions

1. **Consumer product first:** WeChat-inspired compact native discovery, not a chat client. Browser consumer surface is explicitly a design/development preview.
2. **Local-first persistence:** persistent PGlite is the default because Docker is unavailable on this machine. It runs PostgreSQL in-process; external PostgreSQL via pg is selectable. Drizzle parameterized SQL is shared across drivers; reviewed SQL migrations own constraints/triggers.
3. **Storage:** filesystem content-addressed ZIPs enable offline local development without MinIO. An S3-compatible adapter supports the documented MinIO setup. Cloud operations are not certified by local filesystem tests.
4. **Runtime origin:** Android serves verified bundle bytes under synthetic separate HTTPS app origins. This avoids debug DNS/TLS wildcard setup and never exposes arbitrary file URLs. Network subresources not in the verified inventory receive a denied response; CSP is defense in depth, not a promise of perfect containment.
5. **Private authorization:** owners and moderators can preview automatically validated versions before public review. No anonymous preview. Tester invitation management is deferred to alpha.
6. **Public authorization:** approval, publication and current app/developer activity are checked server-side. Sessions remain version-pinned across release changes. Pause/suspension revoke running grants. Unreviewed uploads never become browser previews.
7. **Signing:** local Ed25519 key is generated/persisted outside git. Grants bind app, version, origin, files, capabilities and expiry. Debug bootstraps public key locally; release requires independent pinned-key provisioning. Key rotation remains a production gate.
8. **Session lifetime:** 120-second grants; Android renews every 15 seconds. Renewal is authenticated and signature-checked. Network failure closes the running session at the next control check. This restrictive local behavior trades offline use for revocation enforcement.
9. **Bridge:** no addJavascriptInterface. A feature-checked AndroidX message listener accepts main-frame messages only from the exact app origin and validates nonce/method/capability. No permission APIs. Server revalidates analytics capability and payload. SDK-reported completion remains an untrusted engagement signal.
10. **Storage isolation:** DOM storage and service workers are disabled; all WebView cookies are disabled (host authentication uses a separate native client); app bundles use separate origins. Tap Reflex best is in-session only. No promise of persistent per-app storage or background timers.
11. **Upload transport:** bounded authenticated base64 ZIP upload and synchronous validation replace the spec's presigned staging/worker pipeline for the local slice. Limits are 2 MB compressed, 6 MB expanded, 64 files, 2 MB per file and bounded path depth. Production needs streaming staging, timeouts/process isolation and stronger scanning.
12. **Authentication:** deterministic invited local accounts and opaque server sessions. Cookie sessions are HttpOnly/SameSite Strict; mutation header and origin checks mitigate CSRF. Production email/identity verification is not implemented.
13. **Guest migration:** saves/blocks merge without duplicates; sessions, feedback and reports migrate when the guest signs in. Native account credentials never enter mini-app content.
14. **Analytics:** actual session/event counts, version comparison and redacted feedback; exact local counts support test verification. Small-cohort suppression, full retention automation and fraud defenses remain production/alpha gates.
15. **Content review:** moderator decisions are reasoned and audited. Only restricted Android testing executes uploaded content. The dashboard exposes metadata/scan outcomes; no uploaded scripts execute in its origin.
16. **Current Android baseline:** SDK/target 35, min SDK 28 with feature detection. Android API 35 emulator is exercised here. Current Play API-target requirements must be checked at submission.
17. **Scope:** no payments, ads, chat, AI proxy, public uploads or sensitive capabilities. Android App Links require an owned domain and release signing; the local edition supports firsttry:// intent links and metadata landing pages.
18. **Operations:** this is intentionally a local development server, not a production-ready deployment. Production startup is blocked until authentication, TLS, keys, worker isolation, review staffing and independent review are addressed.

19. **Regression isolation:** run browser and native suites sequentially against the local API. They share loopback rate limits; parallel suites can legitimately trigger abuse limits. The native helper checks the instrumentation report because ADB itself may exit zero when JUnit fails.
20. **Intent lifecycle:** the Android activity handles singleTop intents with an event counter so opening the same mini-app deep link twice remains functional; teardown callbacks from disposed WebViews cannot close a new session.
